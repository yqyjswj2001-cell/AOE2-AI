# 关联填写要求

只填写本轮清单内的键。参数卡上的单位、触发方向、同组关系和作用需要一起考虑。空位是参数位置，不必然是独立决策。

## 攻击组

ORB_ATTACK_GROUP_001 = ORB_ATTACK_GROUP_005 = ORB_ATTACK_GROUP_007 = ORB_ATTACK_GROUP_009

ORB_ATTACK_GROUP_002 = ORB_ATTACK_GROUP_006 = ORB_ATTACK_GROUP_008 = ORB_ATTACK_GROUP_010

最小和最大组规模为正整数，最小不得大于最大，二者不得同时为1（与固定停用状态冲突）。组数为非负整数，出击比例为0–100整数。

## 配比和门槛

- 资源份额和出击比例按0–100整数填写。同一完整采集分配的四项合计100；用同一个group_id查询整组后一起决定。
- 文明帝王配比中的石料份额必须小于100，避免其消费者的分母为零。
- 建筑数量、明确的单位/人口数量和游戏时间使用非负整数。具体单位和比较方向以参数卡为准。
- 优势档位、加权战力差、资源盈余差额可能带正负号，不能套用上述非负限制，也不臆测引擎上限。
- 研究与出兵等前后关系见参数卡的constraints_note。不同条件下出现同一个名称，不自动视为同一选择。

已登记的机器约束由主代理检查；参数卡中的文字提醒不都等于机器证明。不一致的答案会被拒绝，不会被工具偷偷改写。动态分类不证明实机效果。
